# Design System — Football News

## Product Context
- **What this is:** A Korean-language weekly newsletter email, one per Premier League club, summarizing that team's matches, transfers, rumors, and storylines from the past 7 days.
- **Who it's for:** Casual Korean-speaking Premier League fans who sign up for exactly one club via a Google Form. Read on mobile, mostly in the Gmail app.
- **Space/industry:** Sports media / fan newsletters (The Athletic, ESPN, Sky Sports email digests).
- **Project type:** Transactional HTML email (not a web app — no browser chrome, no interaction beyond reading and clicking source links).
- **The one visual surface:** `email_sender/smtp_sender.py`'s `EMAIL_STYLES`, applied to markdown generated by `summarizers/llm.py` and rendered via `generate_newsletter.py` → `send_mail.py`. There is no other UI in this repo.

## Aesthetic Direction
- **Direction:** Editorial/Magazine — "매치데이 프로그램" (Matchday Programme). The email should feel like the programme handed out at the stadium for your club, not a system notification or a marketing blast.
- **Decoration level:** Intentional — full-bleed navy banner masthead, gold hairline accents, dotted section dividers. Not minimal (that reads as unstyled, which the May 2026 design audit flagged as the original problem), not maximalist (would fight the long-form reading content).
- **Mood:** Serious sports-journalism register wrapping deliberately casual, social-friendly Korean copy (see `prompt.yml`). The frame says "real reporting on the club you're emotionally invested in"; the voice says "your friend who watches every match." This tension is intentional, not an inconsistency — see Decisions Log.
- **Reference sites:** The Athletic, ESPN, Sky Sports newsletter emails (evaluated by category convention during `/design-shotgun`, not screenshotted).

## Typography

Email clients strip `@font-face`/Google Fonts almost universally, so this system has two layers: what was explored visually, and what actually ships.

- **Aspirational (design-shotgun mockups only, not production):** Oswald (condensed display) for headlines, Noto Serif KR for body.
- **Shipped (what subscribers receive):** System stack only — `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic", "Helvetica Neue", Arial, sans-serif`. The condensed/editorial feel is faked via bold weight + `text-transform: uppercase` + `letter-spacing` on `h1`/`h2`, not an actual condensed typeface.
- **UI/Labels:** Same system stack, `text-transform: uppercase`, `letter-spacing: 1px`, `font-weight: 700` for section labels (h2).
- **Data/Tables:** Same system stack. No monospace/tabular-nums — table content is Korean prose (한줄 요약), not numeric data that needs column alignment.
- **Code:** N/A — no code is rendered in this product.
- **Loading:** N/A — external font loading is unreliable across Gmail/Apple Mail/Outlook, so none is attempted. This is a deliberate constraint, not an oversight.
- **Scale:**
  - h1 (masthead banner): 22px / 1.3 line-height / 700 weight
  - h2 (section label): 13px / 1.4 line-height / 700 weight / uppercase / 1px letter-spacing
  - h2 + p strong (the actual headline text inside "메인 헤드라인"): 20px / 1.4 line-height, enlarged automatically via the `h2 + p strong` selector — no markup changes needed since the LLM already wraps headlines in `**bold**`
  - h3: 16px / 1.4 line-height
  - body (p, li): 16px / 1.7 line-height
  - table th: 12px / uppercase / 0.5px letter-spacing

## Color
- **Approach:** Restrained — one accent (gold) against a navy/cream neutral pairing.
- **Primary (ink/navy):** `#14204d` — masthead banner background, h2/h3/strong/link text, table header background.
- **Accent (gold):** `#c8a24a` — h1 banner border, h2 underline, table header text.
- **Surface (cream):** `#f4f0e6` — the `.wrap` card background (the email content itself).
- **Page background (newsprint tan):** `#d8d2c4` — the `body` background visible as a margin around the card in clients that render full-width backgrounds.
- **Neutrals:** table row dividers `#d8d2c4` (same as page bg, low-contrast on purpose), body text `#2b2a26`.
- **Semantic:** none — this product has no success/warning/error states. It's read-only content.
- **Dark mode:** Not implemented. Email client dark-mode handling (Gmail's auto-invert, Apple Mail's `prefers-color-scheme`) is notoriously inconsistent and can invert a navy banner into something illegible; deliberately out of scope until there's evidence subscribers need it.

## Spacing
- **Base unit:** 4px
- **Density:** Comfortable — 1.7 body line-height, ~28-32px vertical rhythm between sections. Built for sustained reading of long-form content (real newsletters run 60-70 lines), not for a dense dashboard.
- **Scale in use:** 6 (li margin) · 8 (th vertical padding) · 10 (th horizontal padding) · 12 (td padding) · 14 (h2 bottom margin) · 18 (h1 bottom padding) · 20 (table bottom margin) · 22 (h1 top padding) · 24 (wrap horizontal padding) · 28 (wrap vertical padding, hr margin) · 32 (h2 top margin)

## Layout
- **Approach:** Single-column editorial stack. Email format makes multi-column layout unreliable across clients, so hierarchy comes entirely from typography and color, not grid structure.
- **Grid:** N/A (single column, all breakpoints — email clients don't get meaningful viewport-based layout changes)
- **Max content width:** 640px (the email-safe standard; matches what was already in place pre-redesign)
- **Border radius:** 0 everywhere. Sharp corners are a deliberate signal — rounded corners read as "SaaS app," and this system is explicitly opting out of that register in favor of "print programme."

## Motion
- **Approach:** N/A. Email clients don't reliably run CSS transitions or JS, so none is attempted anywhere in this system.
